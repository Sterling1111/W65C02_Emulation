# W65C22 VIA model

The implementation is in `SystemLib/W65C22.h` and `.cpp`. The reference is the
WDC W65C22 (W65C22N/W65C22S) datasheet supplied with this task, September 13,
2010, especially sections 2 and 3. The manufacturer also hosts a
[current datasheet](https://www.westerndesigncenter.com/documentation/w65c22.pdf).

This is a digital, full-PHI2-cycle model. It implements the chip's programmable
functions and observable logic levels/drive directions. It does not simulate
voltages, drive currents, propagation delays, metastability, or damage from
contending drivers. Power-on values unspecified by WDC are initialized to zero
for repeatable runs; control inputs initially read high.

## Register map

Addresses mirror every 16 bytes. `readFromRegisters(address)` and
`writeToRegisters(data, address)` perform register accesses without advancing
time. The register names below are also public `W65C22::Register` constants.

| Offset | Register | Behavior |
| --- | --- | --- |
| 0 | ORB | Output latch on output bits, live/latched pins on input bits; clears CB1 and dependent CB2 flags; writes initiate CB2 handshake/pulse. |
| 1 | ORA | Reads live/latched PA pins, including output pins; reads and writes clear CA1 and dependent CA2 flags and initiate CA2 handshake/pulse. |
| 2, 3 | DDRB, DDRA | One means output; zero means input. Direction changes apply existing output latch contents immediately. |
| 4 | T1CL | Read counter low and clear T1 flag; write latch low only. |
| 5 | T1CH | Read counter high; write latch high, load full counter, arm timeout, clear T1 flag, and lower timer PB7. |
| 6, 7 | T1LL, T1LH | Read/write timer latches without loading counter; writing high clears T1 flag. |
| 8 | T2CL | Read counter low and clear T2 flag; write low latch. |
| 9 | T2CH | Read counter high; write high and load low latch into counter, arm timeout, clear T2 flag. |
| A | SR | Read/write shift register; clear SR flag and restart the bit count/transfer in enabled modes. |
| B | ACR | Input latches, serial mode, T2 count source, T1 repetition and PB7 selection. |
| C | PCR | Control-edge polarity, independent C2 inputs, handshake/pulse/fixed outputs. |
| D | IFR | Sticky event flags; write-one-to-clear bits 0–6. Bit 7 is the OR of enabled pending flags, not writable storage. |
| E | IER | Bit 7 selects set (1) or clear (0) of the written one bits; reads always return bit 7 set. |
| F | ORA_NO_HANDSHAKE | PA access without handshake or flag acknowledgement. |

The 2010 datasheet's Table 2-7 high-latch READ description says "counter";
this model treats offset 7 as the high **latch**, consistent with its register
map and the separate counter at offset 5.

Input latches capture PA/PB on the selected CA1/CB1 edge. Normal port
acknowledgement releases them to live input until the next edge. PB output
bits read the output latch even when an external driver overrides the physical
pin; PA reads the physical pin. Independent C2 flags survive normal port
accesses and require IFR acknowledgement. PCR output modes suppress C2 input
interrupts. The shift register overrides CB1/CB2's peripheral-control functions
as appropriate to its mode.

## Time and timers

`tick(n)` advances n complete PHI2 periods; it never sleeps. An access between
ticks is treated as occurring at the end of the previous bus cycle. The CPU
advances peripherals before each bus transfer, including all RAM/ROM accesses
and internal cycles. Idle clocks during `WAI` and `STP` continue to advance
peripherals. The existing `W65C02` worker provides wall-clock pacing and sleeps
between batches. No second CPU object or VIA worker thread is created.

A timer loaded with N passes through zero and underflows on tick N+1. The IRQ
edge shown at N+1.5 in the datasheet is observed at full-cycle granularity;
half-cycle signal placement is not represented. T1 has a reload cycle after
underflow, giving a repeating period of N+2. As shown in Figure 2-3, its counter
reloads in one-shot mode too, but only the first timeout interrupts or changes
PB7; a high-counter write rearms it. Free-running mode interrupts and toggles
PB7 every period. ACR7 selects timer output and DDRB7 enables the physical
output driver. Latch writes change the next reload without changing the
current countdown.

T2 normally continues decrementing after underflow, but only its first timeout
interrupts until reloaded. With ACR5 set, it decrements on sampled PB6 falling
edges instead of each PHI2 period. Set the input before `tick()`; pulses wholly
between samples are not counted. In T2 serial modes the low counter reloads
from the T2 low latch with the reload interval, producing a CB1 half-period of
N+2 ticks. This is the same low counter exposed through T2CL; PHI2 serial modes
leave T2 independent.

## Serial modes

| ACR bits 4–2 | Operation | Completion |
| --- | --- | --- |
| 000 | Disabled; PCR owns CB1/CB2. | SR flag held clear. |
| 001 | Input using T2-generated CB1. | Stops after eight bits, sets SR flag. |
| 010 | Input using PHI2-derived CB1. | Stops after eight bits, sets SR flag. |
| 011 | Input using external CB1. | Continues; sets SR flag every eight bits. |
| 100 | Repeating output using T2-generated CB1. | Never interrupts; recirculates continuously. |
| 101 | Output using T2-generated CB1. | Stops after eight pulses, holds last CB2 bit, sets SR flag. |
| 110 | Output using PHI2-derived CB1. | Stops after eight pulses, holds last CB2 bit, sets SR flag. |
| 111 | Output using external CB1. | Continues; sets SR flag every eight bits. |

Output is MSB first, recirculating bit 7 into bit 0 on falling CB1 edges.
Input enters bit 0 and shifts toward bit 7, sampled on the PHI2 tick following
CB1's rising edge. Keep CB2 stable through that tick. Internally generated
PHI2 clocks toggle CB1 once per tick (two ticks per bit); the initial falling
edge is emitted two ticks after SR access. T2 clocks use N+2 ticks per half
period. Internal-output completion occurs at the eighth rising edge; external
output counts falling edges, following Figures 2-10 through 2-12.

## Peripheral connections and chip variants

Construct `W65C22 via;` for the S variant or
`W65C22 via(W65C22::Variant::W65C22N);` for N. Logical programming behavior is
shared. S deasserts IRQ with a high drive; N releases its open-drain IRQ.
`irqAsserted()` is active-high logical status for connecting to a CPU.

`setPortAInput(levels, drivenMask)` and `setPortBInput(...)` specify external
pin drivers; each call replaces that port's external levels and mask.
`releasePortA(mask)` / `releasePortB(mask)` disconnect selected drivers. On S,
released PA/PB inputs retain their last digital state as a bus-hold model. N
uses a deterministic high fallback for undriven inputs. Explicit external
levels take precedence when representing an externally forced output pin;
this is not an electrical contention simulation.

`setCA1`, `setCA2`, `setCB1`, `setCB2` supply peripheral control/serial levels.
These boolean inputs represent externally driven logic levels. External CB1
changes cannot affect an internally generated serial clock. `pins()` exposes
PA/PB values and output masks, control-pin levels and drive states, and IRQ.
`setPinCallback(callback)` observes pin/drive changes, including serial clocks
and PB7 transitions. A callback can drive inputs in response to an output,
but must not advance time, recursively change outputs, or acquire the CPU
state mutex again.

The existing `PortBus` remains the LCD adapter. PB writes carry a direction
mask so releasing input lines does not overwrite LCD data. Standalone VIAs
need no LCD or bus connection.

Use the CPU's `stateMutex()` around external VIA access while its worker is
running. Callbacks run on the caller's thread with that same synchronization;
they do not create threads. For example, with a stopped CPU or standalone VIA:

```cpp
W65C22 via;
via.writeToRegisters(0xc0, W65C22::IER); // Enable T1 IRQ.
via.writeToRegisters(9, W65C22::T1CL);
via.writeToRegisters(0, W65C22::T1CH);
via.tick(10);
bool pending = via.irqAsserted();       // true
via.readFromRegisters(W65C22::T1CL);   // Acknowledge T1.
```

`busCycle(cs1, cs2b, read, address, data)` models a whole selected or deselected
bus period and returns `{driving, data}`. Deselected accesses do not touch
registers or acknowledge flags, but time advances. `setRESB(false)` holds the
chip in reset; `setRESB(true)` releases it. Reset clears port/control/interrupt
registers, releases peripheral drivers, and disables timers/serial activity.
It preserves T1/T2 counters and latches and SR as specified by section 3.9.
`reset()` applies the reset action immediately without holding RESB low.
The emulator's **R** key resets both CPU and VIA.

## Validation

`SystemTest/W65C22Tests.cpp` covers register mirroring and side effects, port
readback and latching, all C2 input modes and output handshakes, IRQ masking and
acknowledgement, timer boundaries/reloads/PB7/PB6, all serial modes, reset,
chip selection, variant IRQ drive, and CPU clock/IRQ/WAI integration. Existing
CPU instruction and pacing tests run alongside these tests. The Hello World
ROM is also checked against the expected LCD pixel contents.
